# cbsbd3d App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the playable cbsbd3d site — a three.js cube of 27 suspects that reads a generated puzzle file, enforces the accusation rules, and deploys to GitHub Pages.

**Architecture:** React shell (routing, archive, fetch, game state) around a plain three.js scene owned by one component. The scene is a pure function of the puzzle plus the game state: React never touches three.js objects, and the scene never holds game truth. All game logic lives in a reducer that knows nothing about rendering, so it is testable without a canvas.

**Tech Stack:** TypeScript, React 19, Vite 8, Vitest 4, jsdom, three.js 0.160 (bundled from npm, not a CDN).

**Spec:** `docs/superpowers/specs/2026-09-04-cbsbd3d-design.md`

**Prerequisite:** the generator plan (`2026-09-04-cbsbd3d-generator.md`) is complete, so `puzzles/` holds real files and `shared/puzzle.ts` defines their shape.

**Reference mockup:** `docs/mockup-v34.html` — 33 iterations of settled visual design. It is the specification for every layout constant below. Read it before Task 3.

## Global Constraints

- Board is always 3x3x3. Cell index `i = z*9 + y*3 + x`. Address `A1a` through `C3c`.
- The site is served from a UUID base path in `config/site.json`, generated once and never regenerated.
- three.js, the Twemoji SVGs and the TextGeometry font are all vendored or bundled. The page must load with no third-party network request.
- Red (criminal) and green (innocent) are identical in every dimension. The verdict is colour alone. Never scale one differently from the other.
- Every clue on the board renders at one shared size: the tightest fit across all of them.
- A hidden slice is removed from the scene, not faded.
- WebGL is required; without it the app says so rather than degrading.
- Layout constants from the mockup, to be used verbatim: `HEAD_SMALL = 0.42`, `HEAD_Y = 0.74`, `FACE_Z = 0.04`, `BIG_NAME = [2.10, 0.72]`, `BIG_PROF = [2.00, 0.50]`, `BIG_NAME_Y = 0.14`, `BIG_PROF_Y = -0.52`, `TOP_NAME_Y = 0.78`, `TOP_PROF_Y = 0.50`, `CLUE_W = 2.95`, `CLUE_H = 1.88`, `CLUE_Y = -0.28`, `ADDR_X = -1.16`, `ADDR_Y = 1.20`, `ADDR_SIZE = 0.15`, `ADDR_COL = 0x8ea3bf`, `LAYER_FILL = [0xd6fce9, 0xb8f7d9, 0x9ef2c9]`, `RED = 0xff5a4f`, `GREEN = 0x5ad46a`, `gap = 3.0`, `SPEED = 0.45`, `CAM_Y_MAX = 6`, `ZOOM_MIN = 0.45`, `ZOOM_MAX = 1.7`.

- [ ] **Step 3: Write the geometry**

```ts
export const cellPosition = (i: number, gap: number): [number, number, number] =>
  [(xOf(i) - 1) * gap, (1 - yOf(i)) * gap, (1 - zOf(i)) * gap];

/**
 * Turning only happens about y, so the cube stays as tall as it is but grows to
 * its diagonal sideways. Frame for both, so nothing clips mid-rotation.
 */
export function framingDistance(fov: number, aspect: number, gap: number): number {
  const rv = gap * 1.5 + 1.35;
  const rh = gap * 1.5 * 1.415 + 1.35;
  const v = Math.tan((fov / 2) * (Math.PI / 180));
  return Math.max(rv / v, rh / (v * aspect)) * 1.04;
}
```

`Scene.tsx` creates the renderer, camera (`fov` 45, `ry = 0`, `rx` fixed at 0), a `RoomEnvironment` for lighting, and one `THREE.Group` per cell positioned by `cellPosition`. It sizes the canvas to 80% of viewport height and disposes geometries, materials and the renderer on unmount. If `WebGLRenderingContext` is unavailable it renders a plain message instead.

- [ ] **Step 3: Write the reducer and storage**

`isDeducible(p, s, i)` is true when any of `p.people[i].paths` is fully contained in `s.flipped`. A card with `paths: []` is never guessable and starts revealed.
